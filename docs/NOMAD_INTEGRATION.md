# Контур интеграции NOMAD

Интеграция намеренно не подменена фиктивной реализацией. Текущая система готовит каталог, пакеты, новости, админку и Windows-развёртывание; функции электронной очереди ожидают материалы заказчика.

## Что необходимо получить

- актуальное описание REST/WebSocket API и версию NOMAD;
- тестовый URL, сертификаты и учётные данные;
- список подразделений, очередей, услуг и рабочих мест с идентификаторами;
- форматы событий вызова, обслуживания, завершения и перенаправления;
- протокол печати талона и модель принтера;
- поле/команду NOMAD для выдачи талона посетителю с инвалидностью и формат уведомления специалиста;
- способ включения повышенной громкости голосового вызова на табло электронной очереди;
- правила повторного соединения, heartbeat и подтверждения сообщений;
- тестовые сценарии и контакты ответственного инженера;

Управление компьютером Lenovo и физическое подключение ТВ‑1/ТВ‑2 не входят в нашу зону ответственности.

## Обязательные поля новой редакции ТЗ

Адаптер должен сохранять признак приоритетного сопровождения на всём маршруте талона:

```json
{
  "specialAssistance": true,
  "assistanceType": "PERSON_WITH_DISABILITY",
  "notifyAssignedSpecialist": true
}
```

При назначении такого талона специалисту backend должен передать отдельное уведомление `SPECIAL_ASSISTANCE_REQUIRED`. Для голосового вызова табло должен поддерживаться параметр `accessibleAudioMode: "HIGH_VOLUME"`. Точные имена полей будут сопоставлены с реальным API NOMAD после его передачи заказчиком; эти значения не должны попадать в общедоступные журналы.

## План подключения

1. Добавить отдельный адаптер NOMAD на backend, не помещая секреты в frontend.
2. Сопоставить внутренние услуги и пакеты с NOMAD ID через административные настройки.
3. Реализовать защищённое WebSocket-соединение, heartbeat, повторное подключение и журнал ошибок.
4. Подключить выдачу/печать талона и проверить отсутствие персональных данных в логах.
5. Добавить кнопку «Лицо с инвалидностью» в интерфейс модератора, передавать признак в талоне и показывать уведомление назначенному специалисту.
6. Включить повышенную громкость вызовов на табло и проверить её на реальном оборудовании.
7. Реализовать операторский клиент только после утверждения нативной технологии и протокола.
8. Провести нагрузочную и приёмочную проверку на реальном стенде.

В разделе «Состояние системы» NOMAD и оборудование до этого момента отображаются как «Ожидает интеграции», а не как работающие.
