# Информационный киоск ДГД Алматы

Полноценная информационная система для сенсорного киоска Департамента государственных доходов по городу Алматы. Публичная часть показывает двуязычный каталог услуг без внешних переходов и ввода персональных данных. Защищённая административная панель управляет контентом, сотрудниками, настройками, обезличенной аналитикой и журналом действий.

## Возможности

- крупный сенсорный интерфейс для 1920×1080 и 1080×1920;
- русский и казахский языки, три масштаба текста;
- 41 услуга для стенда 2026 года, 5 категорий, 5 опубликованных пакетов обслуживания и поиск с debounce 300 мс;
- подробная информация об услуге полностью внутри киоска;
- глобальный таймер бездействия с предупреждением и полным сбросом сессии;
- понятные состояния загрузки, отсутствия данных, ошибки API и обслуживания;
- JWT access-token в памяти, ротация refresh-token в HttpOnly cookie;
- роли `SUPER_ADMIN`, `ADMIN`, `EDITOR`;
- CRUD услуг, категорий, пакетов и администраторов с валидацией и подтверждением удаления;
- внутренний новостной эфир с фото/видео, бегущей строкой и двуязычной ротацией;
- мониторинг приложения, PostgreSQL и файлового хранилища;
- системные настройки в PostgreSQL;
- обезличенная аналитика и административный audit log;
- Helmet, ограниченный CORS, rate limit, bcrypt, Zod и единый формат ошибок.

## Стек

Frontend: React 19, Vite, JavaScript, React Router, Axios, Lucide React, обычный CSS.

Backend: Node.js 20+, Express, PostgreSQL 16, Prisma ORM, Zod, bcrypt, JWT, cookie-parser, CORS, Helmet, express-rate-limit.

## Быстрый запуск PostgreSQL через Docker

```bash
docker compose up -d postgres
```

Контейнер создаёт БД `dgd_infokiosk`, пользователя `postgres` и публикует порт `5433`. Для разработки строка подключения:

```env
DATABASE_URL=postgresql://postgres:dgd_dev_password@127.0.0.1:5433/dgd_infokiosk
```

Для остановки используйте `docker compose stop postgres`. Данные сохраняются в именованном томе `dgd_postgres_data`.

## Запуск с установленным PostgreSQL

Создайте базу данных от имени пользователя с правами на создание таблиц:

```sql
CREATE DATABASE dgd_infokiosk;
```

Укажите реальный логин, пароль, адрес и порт в `DATABASE_URL`.

## Установка, миграция и seed

Из корня проекта:

```bash
npm run install:all
npm run db:deploy
npm run db:seed
```

Миграция создаёт таблицы, enum, связи и индексы. Seed идемпотентно создаёт первого `SUPER_ADMIN` из `server/.env`, 5 официальных категорий, 41 государственную услугу для стенда 2026 года и 5 опубликованных пакетов обслуживания. Пакет «Почётный» хранится как неопубликованный черновик до согласования. Устаревшие карточки удаляются из рабочего каталога.

На серверном компьютере после `git pull` применяйте уже готовые миграции без создания новых:

```bash
npm run db:deploy
```

Prisma Client автоматически обновляется при установке зависимостей и перед запуском backend.

После первого входа обязательно смените seed-пароль через раздел «Администраторы».

Для серверного Windows-компьютера без Docker используйте готовый сценарий: [docs/WINDOWS_SERVER.md](docs/WINDOWS_SERVER.md).

## Production и проверка

После `npm run build` backend в режиме `NODE_ENV=production` отдаёт API и готовый интерфейс с одного порта. Полная локальная проверка:

```bash
npm run verify
npm run doctor
```

`verify` включает lint, сборку, API- и UI-тесты, а также Chromium-проверку горизонтального и вертикального Full HD, QHD и 4K с масштабированием. `doctor` проверяет Node.js, обязательные переменные, production-сборку, PostgreSQL и применённые миграции. Перед выпуском используйте `npm run release:check` с production-настройками в `server/.env`.

GitHub Actions выполняет тот же `release:check` с отдельной PostgreSQL и запускает аудит production-зависимостей для каждого workspace. Dependabot еженедельно проверяет обновления. Выпускать релиз следует только из чистого коммита с зелёной проверкой.

## Новости

Публичные маршруты frontend: `/news` и `/news/:newsSlug`. Лента поддерживает русский и казахский языки, главную публикацию, поиск и категории «Важное», «Объявления», «События» и «Новости». По умолчанию используется казахский язык, а переключатель в шапке меняет язык всей ленты и открытой публикации.

Управление публикациями находится в разделе `/admin/news` существующей админ-панели. Для каждой новости редактор хранит отдельные заголовок, краткое описание и полный текст на русском и казахском языках. Там же можно выбирать категорию и порядок в эфире, при желании загружать обложки JPG/PNG/WebP/GIF размером до 5 МБ, публиковать сразу или планировать выпуск, задавать срок актуальности, снимать с публикации и удалять новости. Запланированная новость автоматически появляется после наступления указанного времени, а материал с истёкшим сроком автоматически исчезает из ленты и эфира.

Кнопка «Важная новость» создаёт временное модальное сообщение. Для него администратор обязательно задаёт начало и окончание показа. В активный период оно остаётся открытым поверх текущих новостей и материалов полноэкранного эфира, не меняя порядок обычной ленты, пока посетитель не закроет его вручную. Закрытие действует только в текущем сеансе: после завершения таймера сеанса и возврата к эфиру активное сообщение появляется снова. После окончания заданного периода сообщение автоматически исчезает.

Публичный маршрут `/news` в режиме ожидания работает как полноэкранный корпоративный эфир без шапки и подвала. Каждый слайд сначала полностью показывается на казахском языке, затем тот же слайд — на русском, и только после этого открывается следующий. Интерактивная лента открывается только отдельной кнопкой в верхнем углу, поэтому фантомные касания сенсора не прерывают эфир; после заданного периода бездействия экран автоматически возвращается к ротации. В разделе `/admin/broadcast` можно редактировать двуязычную бегущую строку, продолжительность языковых фаз и таймер возврата, добавлять ежегодные поздравления с днём рождения и загружать фотоматериалы JPG/PNG/WebP/GIF или видеоматериалы MP4/WebM. В бегущую строку автоматически добавляются курсы USD, EUR, CNY и RUB к тенге и текущая погода в Алматы. Браузер получает их только от backend через `/api/news/informer`, внешние ключи во frontend не передаются. При временной потере внешнего источника backend отдаёт последние успешно загруженные данные с признаком `stale`, а при потере API экран использует последний сохранённый эфир и автоматически переподключается. Production-сборка регистрирует service worker для оболочки приложения и показывает двуязычный индикатор сохранённых данных при потере соединения.

Для локальной проверки `INFORMER_PROVIDER=official` использует два разрешённых HTTPS-хоста: `nationalbank.kz` и `api.open-meteo.com`. Для закрытого production-хоста укажите `INFORMER_PROVIDER=api-ninjas` и `API_NINJAS_KEY`: тогда backend обращается только к `api.api-ninjas.com:443`. Рабочий тариф провайдера должен разрешать коммерческое использование и серверное кэширование.

Публичный API:

- `GET /api/news` — опубликованные новости от новых к старым; поддерживает параметры `category` и `search`;
- `GET /api/news/:slug` — полная опубликованная новость.
- `GET /api/exchange-rates/usd-kzt` — официальный курс USD/KZT Национального Банка РК с часовым серверным кешем.

Защищённый API:

- `GET /api/admin/news` и `GET /api/admin/news/:id`;
- `POST /api/admin/news`, `PATCH /api/admin/news/:id`, `DELETE /api/admin/news/:id`;
- `PATCH /api/admin/news/:id/publication` — публикация или снятие с публикации;
- `POST /api/admin/news/images` — загрузка обложки.
- `POST /api/admin/broadcast/media` — загрузка фото или видео для отдельного слайда.

Миграция `20260807090000_news` добавляет таблицу `News`, `20260807150000_news_localization` — отдельные русские и казахские поля публикаций, `20260807180000_broadcast` — элементы эфира и настройки бегущей строки, `20260807200000_broadcast_idle` — таймер возврата к эфиру, а `20260810120000_news_lifecycle_and_broadcast_media` — сроки, порядок и тип медиаматериалов. Перед запуском обновлённого приложения примените миграции и при необходимости демонстрационные записи:

```bash
npm run db:deploy
npm run db:seed
```

## Безопасность и приватность

Публичный интерфейс не содержит внешних ссылок, QR-кодов, переходов в новые вкладки и форм ввода ИИН, БИН, банковских или иных персональных данных. Публичная аналитика не сохраняет IP посетителя. IP и user-agent фиксируются только в защищённом журнале административных действий.

Никогда не публикуйте `server/.env`, реальные JWT-секреты и production-пароли. Перед эксплуатацией ограничьте сетевой доступ к PostgreSQL и настройте резервное копирование.
